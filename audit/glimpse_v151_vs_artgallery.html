三 · 关键差异代码实证

3.1 【P0】顶部菜单未尊重 KOReader 自身手势设置（真 bug 缺漏）

影响：用户在 KOReader「设置 → 点按与手势 → 手势管理」中把顶部菜单激活改为「下滑」后，artgallery 打开时顶部区域**仍然**唤起 KOReader 顶部菜单（违背用户对 KOReader 的全局意图）。Glimpse v1.5.1 修了此点；artgallery 未修。
风险评估：低（只新增一个条件判断；行为更收敛，不会变奇怪）；ROI：纯收益，10 行内修复，无视觉副作用。

Glimpse v1.5.1 main.lua:4201-4206

if self.on_show_menu and G_reader_settings:nilOrTrue(TOP_MENU_KEY)
   and G_reader_settings:readSetting("activate_menu") ~= "swipe"
   and self:_inTopMenuZone(ges.pos) then
    self.on_show_menu()
    return true
end

artgallery main.lua:3703-3708（缺漏的那一行）

if self.on_show_menu and G_reader_settings:nilOrTrue(TOP_MENU_KEY)
   -- artgallery 未检查 KOReader 自身的 activate_menu →「下滑」用户会被「点按顶部」抢回菜单
   and not (self._fullscreen and self._chrome_hidden)
   and self:_inTopMenuZone(ges.pos) then
    self.on_show_menu()
    return true
end

3.2 【P1】图库标题区：页码不醒目 + 缩略图不左对齐（UX 改进）

影响：v1.5.1 把「第 X 页 / 共 Y 页」作为黑体大号醒目标签放 line-2 左；把「N 张图片」字数变副标题灰字小号放 line-1 右；同时缩略图改 LeftContainer（左对齐与标题基线一致）。artgallery 是「page 在 line-1 右侧灰字小号、副标题在 line-2 左」「缩略图 CenterContainer」，e-ink 扫一眼难以瞄到「第几页」。
风险评估：低（仅布局参数微调 + 容器替换；不动逻辑、不动触摸区）；ROI：墨水屏可读性提升明显。

3.3 【P2】宽版图库 4 列（视觉调整）

Glimpse v1.5.1 main.lua:3403

-- A top/bottom band is full screen width but short, so 3 columns leave few

artgallery 没有「图库顶/底布局」概念（默认侧拉 + 顶拉才支持），只有 side/portrait_pos 两种摆放方式（参见 PORTRAIT_POS_KEY = "artgallery_portrait_pos"）。如要吸收，须先确认是否要打开「顶部 / 底部横带」布局。
ROI：偏低——artgallery 已经有「列数」设置，再加「横带 4 列」只是 4–6 行分支修改，且只在本来就少见的顶/底布局下生效。视觉收益有限。

3.5 【SKIP】迷你地图 letterbox 截断 — artgallery 本就无此特性

Glimpse 的迷你地图（GlimpseMiniMap）是它独有的「放大查看时显示缩略鸟瞰图」功能。artgallery 从未引入迷你地图，只用「双击↔最大放大」+「双指捏合」就够看了。
不吸收的理由：
  1. 这是「可加可不加的新特性」，不是「必须修的差距」；
  2. KPW3 屏小（1072 行），双击 + 捏合已覆盖缩放场景；
  3. 新增迷你地图会显著增大代码量（V1.5.1 用了约 200+ 行），背离我们对真实 bug 修复+小优化的克制路线。
如你确实想要迷你地图，可单独讨论——这就不是「吸收差距」而是「新增特性」。

3.6 【P2】设置项重整 — 纯展示维护

Glimpse v1.5.1 把零散选项归入「Settings」子组 + 「Advanced」子组。artgallery 当前是平铺列表 + 仅一个「高级」分组。
建议：等真正要做设置重整时再做（届时一并把 P0/P1/P2 一并吸收）。现阶段不单独排期。
