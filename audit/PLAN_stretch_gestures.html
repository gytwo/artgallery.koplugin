拉伸模式启用缩放手势 · 设计方案

已落地 artgallery.koplugin（KPW3 / KOReader）

缘起：用户在阶段十五审阅后，重新审视当时决策点①（"stretch 态禁用双击放大/捏合"），希望评估在拉伸模式下 重新启用以下四类手势的可行性：双击放大、双指张开放大、双指捏合缩小、按住图片移动。
本文基于已读真实源码（插件工作副本 + KOReader 纯净源码 koreader-kindle-v2026.07.1）撰写，所有行号锚点均经 grep 核验。本方案尚未编码，仅提交审阅。

一、结论：技术上可行，且改动很小

可以启用。拉伸（stretch）与铺满（cover）在「缩放」维度上只有一个区别：

  • scale_factor == 0（fit 态）下，stretch 走 ImageWidget 的 非均匀拉伸（传 scale_factor=nil + 精确 width/height），cover 走 均匀铺满（传 wg_scale=fit）。
  • 一旦进入缩放（scale_factor != 0），二者渲染完全一致——都是均匀比例 + 居中 + 可平移，没有任何"拉伸/非拉伸"差异。

因此"放开缩放"的本质 = 让 stretch 也能从 fit 态进入缩放，且缩放下限=cover 均匀填满。无需改 KOReader 框架，仅插件内：解开 2 道 stretch 守卫 + 修 1 处 渲染分支 + 新增 2 个 缩放入口 override。

二、现状：为什么目前被锁死

阶段十五为 stretch 锁定了缩放，共 3 道守卫，全部在 main.lua 工作副本：

落点（当前行号）守卫内容作用
onArtGalleryDoubleTap :2775if self._fullscreen_fill == "stretch" then return true end双击放大直接被吞
_applyNewScaleFactor :3193if self._fullscreen_fill == "stretch" then return end所有程序化缩放（双击/滚轮/捏合）被忽略——这是核心锁
_refreshScaleFactor :3167if self._fullscreen_fill == "stretch" then return end兜底：不让上游把 scale_factor 由 0 改写成数值，以维持"0=拉伸填满"不变量
不变量（必须保护）：scale_factor == 0 在 stretch 下恒表示"非均匀拉伸填满"。onTap 的"已放大"分支、页码圆点 pill 的"还原"态、沉浸式显隐逻辑、导航按钮启用/禁用都依赖此不变量。任何改动都不得让 stretch 在 fit 态把 scale_factor 改写成非 0。

三、核心难点：从"填满态"进入缩放的数学

上游 onZoomIn(inc)（imageviewer.lua:703）计算：

-- 上游逻辑
function ImageViewer:onZoomIn(inc)
    self:_refreshScaleFactor()        -- stretch 下此处早返回，scale_factor 仍是 0
    local new_factor = self.scale_factor * (1 + inc)  -- = 0 * (1+inc) = 0 ！
    self:_applyNewScaleFactor(new_factor)
end

若 scale_factor==0 而 _refreshScaleFactor 早返回（不解析 0→数值），则 new_factor 恒为 0，_applyNewScaleFactor(0) 会按"缩放回下限"直接归 0——双指张开/捏合从填满态根本无法进入缩放。这是放开手势的真正坑，必须单独处理（见第五节 onZoomIn/onZoomOut override）。

手势上游入口当前被锁原因放开方式可行性
双击放大 onArtGalleryDoubleTap → _applyNewScaleFactor(_maxScale()) :2775 早返回吞掉 移除该早返回即可；逻辑与 cover 完全一致（0↔_maxScale） ✓ 直接可用
双指张开放大 onSpread → onZoomIn 经 _applyNewScaleFactor :3193 守卫 解守卫 + 新增 onZoomIn override 修复"0 基数"坑 ✓ 修坑后可用

五、具体改动点（按函数）

1. _new_image_wg（~1821）· 渲染分支 改

-- 现状（无条件 nil）：
if self._fullscreen_fill == "stretch" then wg_scale = nil end
-- 改为（仅 fit 态非均匀拉伸；已缩放则走均匀数字）：
if self._fullscreen_fill == "stretch" and self.scale_factor == 0 then wg_scale = nil end
R1（必修）：若不收窄为 scale_factor==0，已缩放的 stretch 会被继续传 nil → 缩放视图也被非均匀拉伸变形，违背"缩放后均匀"的设计。这是本方案最关键的一行。

2. _computeFitScaleFactor（~3126）· 下限计算 改

-- 让 stretch 的缩放下限 = 均匀铺满（cover），与"填满意图"一致：
local cover = self._fullscreen_fill == "cover" or self._fullscreen_fill == "stretch"

仅影响 _applyNewScaleFactor 的下限判定；非 stretch 的 fit 渲染路径不调用它。

3. _refreshScaleFactor（~3167）· 保留早返回 + 补缓存 改

if self._fullscreen_fill == "stretch" then
    self._fit_scale_factor = self:_computeFitScaleFactor()  -- 缓存 cover 下限，供 _applyNewScaleFactor 使用
    return  -- 关键：保持 scale_factor==0=拉伸填满，不被上游改写
end
不变量保护：此早返回必须保留。若误删，stretch 在 fit 态 scale_factor 会被改写成数值 → onTap 误判"已放大"（pill 变"还原"、禁切图、沉浸式显隐失效）。

4. _applyNewScaleFactor（~3193）· 解核心锁 删

-- 删除此行：
-- if self._fullscreen_fill == "stretch" then return end

删除后缩放数学正常跑：new_factor > 下限(cover) → 均匀缩放；new_factor ≤ 下限 → 归 0（回到非均匀填满）。

5. onArtGalleryDoubleTap（~2775）· 解早返回 删

-- 删除此行：
-- if self._fullscreen_fill == "stretch" then return true end

删除后双击行为同 cover：was_fit(0=填满) → 跳到 _maxScale() 均匀放大；已放大 → 归 0 填满。

6. 新增 onZoomIn / onZoomOut override 加

function ArtGalleryViewer:onZoomIn(inc)
    -- 从"拉伸填满态"(scale_factor==0)进入缩放：以 cover 下限为基数，
    -- 否则 0*(1+inc)=0 永远进不了缩放（见第三节）。
    if self._fullscreen_fill == "stretch" and self.scale_factor == 0 then
        local floor = self:_computeFitScaleFactor() -- cover 均匀填满比例
        inc = inc or 0.2
        self:_applyNewScaleFactor(floor * (1 + inc))
        return true
    end
    return ImageViewer.onZoomIn(self, inc)
end

function ArtGalleryViewer:onZoomOut(dec)
    -- 已在"拉伸填满态"：再缩小无意义（已是最满），停在填满。
    if self._fullscreen_fill == "stretch" and self.scale_factor == 0 then
        return true
    end
    return ImageViewer.onZoomOut(self, dec)
end
说明：onSpread（双指张开）调 onZoomIn、onPinch（双指捏合）调 onZoomOut，故这 2 个 override 一并对双指手势生效。插件已 override 多个 ImageViewer 方法，新增这两个风格一致、无冲突。

六、UX 建议（待你拍板）

  • 双击跳到哪里？ 默认同 cover：直接跳到 _maxScale()（100% 原生，最清晰）。可选：改为跳到 min(_maxScale, 下限×2) 的中度放大，更平缓。推荐沿用 cover 行为（一致、简单）。
  • 缩放回弹：捏合/缩小到 ≤ cover 下限时，自动归 0 回到"非均匀填满"——视觉上从"均匀填满(裁切)"平滑切回"拉伸填满(变形)"。是否要这个 snap？推荐保留（与 cover 模式缩放回弹到 fit 的体感一致）。
  • 变形确认弹窗：仅进入 stretch fit 时弹一次（已持久化 artgallery_stretch_warned）。缩放/平移不重弹——合理，因为缩放后是均匀无变形。
  • 沉浸式（chrome 隐藏）：双击在隐藏态仍走 _checkDoubleTap，会取消 350ms 自动隐藏定时器——放开缩放后此行为不变，无冲突。
